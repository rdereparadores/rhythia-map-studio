# Internationalization

The desktop app supports English and Spanish. The language selector updates the interface without restarting and stores the choice as a local preference, not in the project file.

Song titles, paths and other user-provided values retain their original content. Native file-picker controls follow the Windows language; the app translates their titles and filters.

## Add a language

1. Copy `src/rhythia_studio/locales/es.json` to a new catalog such as `fr.json`.
2. Set `name` to the language's native name, for example `Français`, and `locale` to its Qt locale, such as `fr_FR`.
3. Translate the values in `messages`. Preserve the keys and placeholder names such as `{count}`, `{detail}` and `{level}`.
4. Run the checks below and review the basic and advanced interfaces for clipping and wrapping.
5. Rebuild the executable to include the new catalog.

The selector discovers packaged catalogs automatically. Supported catalog filenames use a two-letter language code, optionally followed by an uppercase region, such as `pt_BR.json`.

```powershell
.venv\Scripts\python -m unittest discover -s tests -v
.venv\Scripts\python tools/preview_ui.py "path\to\project.rmapproj" dist/previews --english --compact
```

The preview helper captures the interface without playing audio. Its `--english` flag selects English; inspect additional languages through the app's selector.

## Message keys and parameters

English source strings are message identifiers. Translate their catalog values while preserving keys and placeholders. A missing translation falls back to the English key; an unknown language falls back to English. Existing local language preferences are retained.

Use explicit parameters rather than formatting text before translation:

```python
# In the UI: translate a template using explicit values.
window.t("{level} · {count} notes · Ready to export", level=level_label, count=note_count)

# In a service: preserve the message structure across the worker boundary.
from rhythia_studio.messages import Message, MessageError

progress(Message("Analyzing separated track: {source}…", source=source_name))
raise MessageError("The {source} track is not aligned with the song.", source=source_name)
```

`Message` remains string-compatible for logs and progress consumers. `MessageError` carries the same structured information in a `ValueError`. The translator uses the template and values directly; it does not parse a completed sentence to recover parameters.

Do not pass a song title or path to the translator as a message key. Pass user content as a parameter so braces or words matching catalog entries remain unchanged.

## Controls and persisted values

- Define each combo box's canonical value when adding its item. Read `currentData()` rather than comparing translated labels.
- Keep canonical difficulty, style and priority IDs in English.
- Add new static UI text to every catalog.
- Mark controls updated by application logic with `setProperty("dynamicText", True)`.
- Register new widget-property types in `UiTranslations` when needed.

Spanish text belongs in the Spanish catalog.

## Implementation and checks

| Module | Responsibility |
| --- | --- |
| `messages.py` | Framework-independent messages and errors |
| `i18n.py` | Catalog discovery, placeholder validation and translation |
| `ui/localization.py` | Static control bindings and signal blocking during translation |
| `ui/dialogs.py` | Application dialog titles, text and buttons |
| `ui/window.py` | Language selection, local preferences and dynamic presentation |

Tests check catalog key coverage, placeholder consistency, fallback behavior, language persistence, user-content preservation and generation with canonical map keys after switching languages.
